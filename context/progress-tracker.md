- **Unit 20 — `mirror` (reflejo git fiel, mismo hash)**: comando nuevo `teleport mirror [profile]` que avanza la rama del remoto a tus commits locales con **hash y mensaje idénticos**, dejando el working tree remoto limpio. A diferencia de `beam` (copia contenidos de archivos por SFTP, deja el tree sucio, no toca la historia git), `mirror` transfiere los **objetos git** vía `git bundle` → el `git log` del server queda idéntico. Hash preservado por construcción (no re-commitea). Picker de **selección única** (`RunMirrorTargetPicker` en `internal/tui/mirrortargetpicker.go`): eliges hasta qué commit avanzar; el tramo es siempre el prefijo contiguo `remoteHEAD..elegido`, lo que garantiza el hash (huecos = imposible mantener hash → eso es beam). `-a` avanza a HEAD sin picker (requerido en headless, Unit 19); `-c` encadena `cleanRemote`; `-f` permite non-ff (`reset --hard`) tras confirmación (headless exige `-y`/`--no-input`); repo remoto unborn/vacío se bootstrapea con bundle completo. Mecánica: `git.BundleTo(base,tip,dst)` (temp ref `refs/teleport/mirror` + `git bundle create`), SFTP a `<path>/.git/teleport-mirror.bundle`, remoto `bundle verify` → `fetch refs/teleport/mirror` → `merge --ff-only` (o `reset --hard`), limpieza del bundle. Nuevos helpers git `RevParse`/`IsAncestor`/`MergeBase`/`CommitsBetween`/`BundleTo`. Avanza la rama *checked out* del remoto (no hace checkout por ti; el nombre de rama no afecta el hash, solo la ancestría decide ff). Sin estado nuevo en config (remoteHEAD es la fuente de verdad). Honra `--json` (`{command,target,branch,from,to,commits[],fast_forward,forced}`) y el contrato de exit codes. Verificado con simulación local+remoto: mismo hash en tramo completo y parcial, bootstrap unborn, guard headless (exit 2 + JSON hint). Falta verificación contra SSH real. Spec en `context/specs/20-mirror.md`.

Ni la validación de `ship` ni la semántica de `sync` se tocaron — `push` es el escape hatch explícito. **Nombre**: `push` (no `send`/`put`/`copy`) por ser el término universal de "manda estos bytes" y par simétrico de `pull`. **Destino**: `resolvePushDest(base, local, to, single)` es función pura; sin `--to` el destino espeja la ruta relativa al **cwd** (no al root de git — push no llama a git); con `--to` y un solo path, `--to` es la ruta destino exacta (`push web/dist --to web/dist.new` renombra el árbol), con varios es directorio padre + basename. **Invariante nueva**: `push` nunca escribe fuera del `path` del perfil — `--to` relativo obligatorio y containment check tras `path.Clean` (rutas remotas con `path`, locales con `filepath`, para no emitir `\` en Windows). **Recolección antes de subir**: `collectPushItems`/`walkPushDir` recorren todo primero, así un path inexistente, symlink roto, ciclo de symlinks o tipo no soportado aborta con el remoto intacto; symlinks se siguen (se sube el contenido) con guard de ciclos por-rama vía `EvalSymlinks` + `defer delete` (dos symlinks hermanos al mismo dir son duplicado, no ciclo). Directorios recursivos; todos los dirs del árbol (incluidos los vacíos) se crean con el nuevo `ssh.Client.MkdirAll`, ordenados parents-first. **Permisos**: solo el bit de ejecución (`0755`/`0644` vía `pushMode`), con nuevo `ssh.Client.Chmod` — necesario porque `SFTP.Create` conserva el modo de un archivo remoto ya existente. **Sin `--delete` en v1** (borrar en remoto es otra clase de riesgo): el reemplazo limpio es push a dir nuevo + swap en un `--then`. Verificación por tamaño gratis (`verifyUpload`) y `--checksum` compara SHA256 en ambos lados (reusa `RemoteSHA256` + el `localSHA256` que ya existía en `status.go`). `--dry-run` imprime el plan y **no conecta**. `--then`/`-t` repetible vía `registerThenFlag` + `-y`; nombres validados antes de subir. No toca `last_sync` (eso describe paridad git). JSON: `{command,target,dry_run?,sent,bytes,verified,files[],actions[]}`. Arg parsing: el último arg es perfil solo si existe en el config **y** no existe como path local. Tests table-driven en `cmd/push_test.go` (destino + rechazo de escapes `../`/absolutos, recolección con árbol real vía `t.Chdir`, orden parents-first, errores, `pushMode`). Verificado: `gofmt`/`vet`/`test ./...`/`build` limpios + smoke local (JSON de una línea, exit 2 nombrando `-y` sin TTY, exit 1 en escapes) + **smoke SFTP real** contra un host en un directorio desechable (`/tmp/...`, borrado al terminar): 4 archivos con SHA256 idénticos, bit de ejecución preservado (`0755` vs `0644`), directorio vacío creado, 0 symlinks en remoto (contenido subido), `--to` renombrando el árbol, destino no escribible fallando ruidosamente, y `--then` fallido propagando exit 1 con el resultado anidado. Spec en `context/specs/28-push.md`.

## Unit 14 Summary

- **Unit 14 — Ship**: new top-level `teleport ship <bin>` subcommand for deploying built CLI binaries to a remote `bin/` directory in three automated steps: SFTP upload → `chmod +x` → `mv` into place (with sudo escalation when the SSH user can't write the destination). Target OS is detected from magic bytes (ELF→linux, Mach-O incl. fat→macos, MZ/PE→windows) by the new `internal/bindetect` package and selects one of up to three bin profiles stored in `~/.config/teleport/config.toml` under `[bin_profiles.<os>]`. Bin profiles live alongside sync profiles in `GlobalConfig.BinProfiles` (`map[string]BinProfile`, validated on load — unknown OS keys raise a decode error). `internal/ssh/client.go` adds `RemoteWritable` (POSIX `[ -w dir ]` probe) and `RunCommandStdin` (used to feed the sudo password via stdin so it never appears in the remote process list). Overwrite is silent (`mv -f`). When sudo prompts and the user cancels, the binary is left under `/tmp/teleport-ship-<pid>-<ts>/<name>` and the message points there. `teleport init` was rewritten around a `huh.MultiSelect` that lets the user pick any combination of `Sync profile` and `Bin profile — {Linux, macOS, Windows}`; the sync flow is preserved when chosen and per-OS bin flows reuse the host picker plus a header-parameterised `tui.RunDirPickerWith` (defaults: `/usr/local/bin` for linux/macos, `/` for windows). `teleport profiles` now prints two labeled sections, omitting either when empty. Help table and examples in `cmd/help.go` updated; no new third-party deps.

## Architecture Decisions

- **bubbletea v2 over v1**: v2 changes `Init()` to return `tea.Cmd` (not `(Model, Cmd)`) and `View()` to return `tea.View` (not string). All models must use `tea.NewView(s)`.
- **No CGO**: binary must cross-compile; all dependencies are pure Go.
- **BurntSushi/toml for config**: chosen over `encoding/json` for human-readable, comment-friendly config files that users may edit manually.
- **`InsecureIgnoreHostKey` fallback**: used when `~/.ssh/known_hosts` is missing or unreadable, to avoid blocking the init flow on first use. Acceptable for a local developer tool; not acceptable for production services.
